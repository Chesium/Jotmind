## Codebase Patterns
- Environment has ONLY Node 18. Pin tooling to Node-18-compatible versions: Vite 5, Vitest 2, ESLint 9, TypeScript 5.x, pnpm 9. Latest pnpm needs Node 22+.
- pnpm is installed globally at ~/.npm-global/bin (npm prefix set to ~/.npm-global). Prepend `~/.npm-global/bin` to PATH in every shell: `export PATH="$HOME/.npm-global/bin:$PATH"`.
- Monorepo = pnpm workspace (`apps/*`, `packages/*`). Shared package `@jotmind/schemas` exports TS source (`./src/index.ts`), NOT built dist, so tsc (moduleResolution: Bundler) + Vite resolve directly with no build step.
- Do NOT add TS project `references` from apps to packages/schemas — composite refs make tsc resolve unbuilt dist/*.d.ts and fail with TS6305. Rely on package `exports` -> source.
- tsconfig.base.json is strict with `verbatimModuleSyntax` -> import types with `import { type X }`. Relative imports use `.js` extensions even in .ts/.tsx (ESM).
- Validation: `pnpm verify:quick` (format:check+typecheck+lint+test) for fast loop, `pnpm verify` for full (adds test:api, test:e2e). `pnpm test` excludes @jotmind/api (run via `pnpm test:api`).
- Playwright browsers must be installed once: `pnpm --filter @jotmind/web exec playwright install chromium`.
- Prettier ignores Ralph scaffolding (prd.json, progress.txt, prompt.md, .agents, etc.) via .prettierignore. Add new non-source top-level files there if they break format:check.
- DB stack = PostgreSQL 18 + Apache AGE 1.7.0 + pgvector 0.8.1 via infra/db/Dockerfile (FROM apache/age:latest, compile pgvector). pgvector MUST be >= v0.8.1 (older fails to build on PG 18). PG 18 docker volume MUST mount at /var/lib/postgresql (NOT /data) or the container exits.
- ORM = Drizzle (drizzle-orm + postgres-js + drizzle-kit) in apps/api. Schema: apps/api/src/db/schema.ts; generate: `pnpm --filter @jotmind/api db:generate`; apply: `db:migrate`. Commit generated apps/api/drizzle/** (SQL + meta/).
- DB access gated on DATABASE_URL: when unset, checkDatabaseHealth() -> configured:false and /api/health stays ok. DB-needing tests use describe.skipIf(!process.env.DATABASE_URL) so default test:api is green without infra.
- DB-backed routes: use an injectable store interface (e.g. AuthStore) + DB impl + in-memory fake; inject via createApp options (createApp({checkDatabase, authStore})). Lets route handlers be unit-tested with no live DB. Mirror this for new domains.
- @node-rs/argon2 `Algorithm` is an ambient const enum -> cannot value-import under verbatimModuleSyntax. Use numeric literal: `const X: Algorithm = 2 as Algorithm` (Argon2id===2). Same caution for any ambient const enum dependency.
- Auth: Argon2id passwords, PG-backed sessions (sessions table), HTTP-only `jm_session` cookie, CSRF synchronizer token (`jm_csrf` readable cookie + `x-csrf-token` header) on cookie-auth mutations. System account role (admin|member) is separate from KB-scoped roles (US-004+). Web mutations need credentials:include + x-csrf-token.
- dev-browser skill is NOT available in this env. For required browser verification of UI stories, use Playwright + Chromium (installed) against the running API (write a temp e2e spec, run, screenshot, then delete it).
- Canonical graph writes (entities US-008, claims US-009, etc.) must write the relational row, enqueueGraphOutbox(tx,...), AND an audit_events row in ONE transaction. dbGraphWriteStore (graph/store.ts) only does outbox; per-domain stores (dbEntityStore) add the audit insert. Reads filter `deleted_at IS NULL` and scope by knowledgeBaseId.
- Nested KB-scoped routes: a separate Router({mergeParams:true}) mounted at /api/knowledge-bases/:kbId/<thing> (AFTER the KB router, which has no matching nested route so it falls through). Reuse kbStore.getRole in a local requireKbRole(min): 404 for non-members (hide existence), 403 for too-low role. Reads need viewer; mutations need editor + requireCsrf.
- Web interaction tests: @testing-library/user-event is NOT installed — use fireEvent from @testing-library/react. For real-browser verification, write a TEMP playwright config with two webServers (API w/ DATABASE_URL env + reuseExistingServer:true, web dev), truncate DB users first (so first-run setup shows), run, screenshot, then delete the temp files.
- Background work = durable `jobs` table (US-007). Enqueue via dbJobStore.enqueue({type,...}); register handlers in apps/api/src/jobs/handlers.ts:defaultJobHandlers. Workers claim atomically via claimNext (FOR UPDATE SKIP LOCKED in a tx); runNextJob handles capped-exponential-backoff retry + dead-letter. Two run modes share runNextJob: `pnpm --filter @jotmind/api worker` (separate process) and startInProcessWorker (WORKER_INLINE=true in server.ts). Don't invent new background loops.
